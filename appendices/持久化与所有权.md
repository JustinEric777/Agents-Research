# 附录 B：持久化与所有权

持久化不等于 durable execution。当前四个 Agent 的比较必须同时回答「数据是否留下」和「谁能继续执行」。

## 统一对象模型

| 对象 | 必答问题 |
|---|---|
| Session | 谁创建、谁可读写、谁可以恢复、谁可以关闭 |
| Message / Event | 谁产生、序号如何分配、是否允许重复、是否可重放 |
| Task | 谁发起、预算归谁、完成条件是什么、失败如何重试 |
| Child Agent | parent、initiator、scope、工具权、上下文来源、回收者 |
| Background Job | claim / lease、心跳、重启后状态、取消传播、输出回注 |
| Approval | 请求者、决策者、适用范围、过期时间、审计记录 |

## Durable contract

每章都应给出以下七项结论：

1. **幂等键**：重复提交是否会产生重复副作用。
2. **checkpoint**：执行进度写入哪里，写入时机是什么。
3. **lease**：多个 worker 如何避免同时拥有同一工作。
4. **recovery**：进程、机器或网络中断后从哪个状态继续。
5. **cancellation**：取消是否级联，取消后是否等待子任务收敛。
6. **replay**：恢复时重放的是事件、消息、快照还是外部状态。
7. **migration**：schema 变化时旧数据如何读取、拒绝或转换。

## 验收场景

| 编号 | 场景 | 通过条件 |
|---|---|---|
| D01 | 工具执行中进程退出 | 恢复后不会静默丢失调用状态 |
| D02 | 同一任务重复投递 | 外部副作用最多执行一次，或明确可补偿 |
| D03 | parent 取消 child | child 最终停止，状态和原因可查询 |
| D04 | worker 失联 | lease 过期后可被安全接管 |
| D05 | 输出晚于 parent | 输出有归属，不能写入错误 session |
| D06 | schema 增加未知字段 | 兼容策略可观察且不会破坏重放 |

这份附录应与第 7、8、9、14 章交叉核对；任何一章缺少 owner、lease 或 recovery 结论，都视为分析不完整。
