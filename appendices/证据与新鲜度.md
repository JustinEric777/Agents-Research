# 附录 A：证据与新鲜度

本附录规定当前版本研究的证据边界。版本、提交、发行产物和章节优先级以仓库根目录的 `sources.lock.json` 为唯一输入。

## 证据等级

| 等级 | 允许表达 | 不允许表达 |
|---|---|---|
| `code` | 官方源码中的类型、流程、错误处理和配置行为 | 把未执行路径写成线上默认行为 |
| `release` | 官方 release、npm 产物、帮助文本和能力清单 | 把发行元数据扩展成源码实现细节 |
| `probe` | 固定输入、固定环境下观察到的实际行为 | 用一次探针推断所有配置组合 |
| `inference` | 明确标为推断的设计解释 | 把推断写成代码事实 |

`code` 之下的两种引用要额外写明限定，这是 `code` 级引用的硬约束，不是另立一级：**源码注释**须说明「注释给出」，**`feature()` 门控路径**须说明「还原版可见 ≠ 发布版启用」。凡不满足最低引用格式的结论，降级为 `inference` 或标记 `unverified`。

## 最低引用格式

每条代码级结论至少包含：

1. 项目名和当前 `ref`。
2. 仓库相对路径与行号；源码不可读时改用 release 字段或探针编号。
3. 该证据支持的具体行为，而不是只贴文件名。
4. 未覆盖的配置、平台或 feature gate。

## 新鲜度门槛

| 对象 | 必须更新的字段 | 失效条件 |
|---|---|---|
| Git 项目 | `ref`、`commit`、采集日期 | tag 移动、提交不可访问、上游发布新稳定版本 |
| 二进制 / npm | 包版本、平台、发布元数据 | 包版本变化或平台构建变化 |
| 章节 | `reviewed_at`、`baseline`、`evidence_mode`、`review_priority` | 来源锁变更或章节引用路径变化 |
| 探针 | 输入、环境、输出摘要、运行日期 | 默认配置、权限、协议或模型能力变化 |

## CI 检查

```sh
ruby tools/check_sources.rb
ruby tools/check_citations.rb
ruby tools/build_refresh_matrix.rb --output reports/current-matrix.md
```

校验器只负责发现证据结构问题，不替代人工判断。遇到无法直接验证的行为，章节必须保留 `inference` 或 `unverified` 标记，不能为了通过检查而补写不存在的源码行。
