## 这次基线是怎么定的

四个项目「最新」的可达性并不一致，因此取法也不同。下表是本轮的判定依据，避免把「没有新标签」误读成「没有新代码」。

| 项目 | 取法 | 判定依据 |
|---|---|---|
| pi | 取主干末端 | 标签 `v1.5.2` 之后 `main` 又推进 156 个提交，其中含 `feat(durable)!` 级别的破坏性变更（可挂起工作、code-mode 命名空间改由扩展声明）；只跟标签会漏掉这些结构性变化。相对上一基线 `b4afddd`（= `v1.5.2`）累计 156 个 first-parent 提交 |
| dsh | 取主干末端 | 新标签 `dsh-v0.2.2-rc.3` 已由 release 分支合回 `master`，`master` 又在标签之后推进 608 个提交；相对上一基线 `e8f7b93a` 累计 64 个 first-parent 提交 |
| codex | 取主干末端 | codex 的主干发布节奏快于标签，标签不构成有效锚点；相对上一基线 `bb64b89` 累计 1263 个 first-parent 提交 |
| Claude Code | 取 npm 发行物 | 官方只发布平台二进制包，无公开源码标签；本地还原树不作为同版本证据 |

> 主干末端是移动目标。报告中的每条源码断言都绑定到上表的固定提交，而不是「master 上的某一个位置」。
