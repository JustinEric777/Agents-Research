# 附录 C：安全与兼容性

权限、MCP、插件、网络和诊断不是互相独立的功能点。当前复核统一使用「输入到副作用」的数据流来检查安全边界。

## 端到端威胁面

```text
用户输入 / 项目指令
        ↓
上下文组装 → 模型输出 → 工具 schema / MCP 能力发现
        ↓                  ↓
审批与策略 ───────────→ 子进程 / 文件 / 网络 / 外部服务
        ↓
事件、遥测、诊断与恢复产物
```

每个箭头都要回答：数据是否可信、是否可被注入、是否经过最小权限检查、是否可能把秘密带出边界。

## 必查控制点

| 控制点 | 检查问题 |
|---|---|
| 项目指令 | 不可信目录中的指令能否覆盖系统策略 |
| 工具 schema | 描述文本和参数是否能诱导越权调用 |
| MCP | server 身份、OAuth scope、能力变更和断连如何处理 |
| 插件 | 安装来源、依赖、卸载残留和热加载边界是什么 |
| 网络 | DNS、代理、loopback、远程绑定和凭证如何限制 |
| 子 Agent | parent 权限是否意外扩大，审批是否可继承 |
| 诊断 | transcript、环境变量、URL 和 token 如何脱敏 |
| 协议 | 未知字段、未知事件和不兼容版本如何失败 |

## 兼容性矩阵

| 维度 | 兼容性问题 | 记录方式 |
|---|---|---|
| 握手 | 是否声明版本和能力 | 请求 / 响应字段与拒绝条件 |
| schema | 新增字段是否向前兼容 | unknown-field 策略 |
| 事件 | 新事件能否安全忽略 | `ignorable`、拒绝或降级行为 |
| 传输 | 断连、重连、重复消息如何处理 | 序号、游标、幂等键 |
| 审批 | 决策范围和有效期是否明确 | once / session / persistent 语义 |
| 数据 | 当前格式如何读取及拒绝不兼容数据 | 解码器、校验与不可恢复错误 |

验收时必须同时通过安全和兼容性检查；只证明「能连上」或「能拒绝」都不足以证明协议可用于生产。
