# 附录 D：源码复核矩阵

本矩阵用于阅读和复核最终分析。每项结论应说明项目、当前来源、文件行段、适用条件与设计取舍；资料不足时保留推断或待确认。

| 范围 | 源码核查内容 | 需要的证据 |
|---|---|---|
| L1–L2 | 配置优先级、凭据来源、提示词注入和预算 | 解析入口、合并规则、分节与截断条件 |
| L3–L5 | 循环、工具定义、调度、权限门与结算 | 声明、注释契约和实际分支分别列明 |
| L6–L8 | 压缩、消息、事件、存储与恢复 | 状态源、日志位置、检查点与恢复读取路径 |
| L9–L10 | 子任务、配置继承、审批和安全边界 | 主体、范围、继承与授权路径 |
| L11–L13 | Provider、插件与 MCP | 能力投影、注册、注销、认证和资源读取 |
| L14–L15 | 作业与协议 | 内存/持久化边界、初始化、字段与错误 |
| L16–L17 | 呈现面、诊断和可观测性 | 投影状态、错误出口和数据字段 |

## 关键问题

- 四个项目是否使用了同一比较维度，而不是只比较名称？
- 当前文件和行段能否直接支持这条结论？
- 字段或类型的存在是否被误写成完整机制保证？
- 注释、条件分支和实验性门控是否说明了范围？
- 异常分支、资源归属和结算边界是否与主流程一起考虑？
- 建议是已有共识、特定场景的取舍，还是分析推断？
- 相反描述是否真正属于同一主体、版本和适用范围？
